# Журнал изменений dream-team

Одна строка на изменение, новые сверху: `- X.Y.Z — ГГГГ-ММ-ДД — что сделано`. Формулировка глагольная, одна фраза, без пояснений; ломающее изменение начинается с `**Breaking:**`. Верхняя строка держит версию `package.json` — `npm test` падает, пока она отстаёт. `dream-team:changelog` печатает верхние строки как есть.

- 4.19.0 — 2026-09-11 — Линза `design` идёт по именованным запахам рефакторинга из общего референса: ярлык становится находкой только там, где изменение делает его стоимость сопровождения конкретной
- 4.19.0 — 2026-09-11 — Дефект, который уже назвал гейт — линтер, типы, статанализ — остаётся находкой той проверки: ревьювер не заводит вторую рядом
- 4.18.0 — 2026-09-11 — Добавлен `hostLabel`: таблица «Затрачено» закрывается строкой диспетчера, а дети сессии вне списка запусков выводятся своими строками — ИТОГО сходится с затратами всей сессии
- 4.17.0 — 2026-09-10 — Гейт проекта убран из разработчика: роль гоняет только тесты изменённого поведения, а линтеры, статанализ, типы, сборки и сьют идут один раз на ревью
- 4.17.0 — 2026-09-10 — Добавлен `checks-run.mjs`: пак ревью запускает проверки отсоединённым процессом во время чтения, ревьюер читает результаты через `--wait` и перезапускает только по сомнению
- 4.17.0 — 2026-09-10 — PHPStan идёт через обёртку конфига с `tmpDir` на рабочее дерево под temp: кэш результата не вытесняется другими чекаутами и греет повторные прогоны
- 4.16.1 — 2026-09-10 — Уточнено, что «пиши» завершает интервью без записи: готовый PRD сначала показывается человеку, обёртка пишет его только после подтверждения
- 4.16.0 — 2026-09-10 — **Breaking:** проверки идут в области изменения: `env-snapshot` выводит по инструменту, как он сужается до изменённых путей или почему не сужается, а сплошной прогон остаётся запасным
- 4.16.0 — 2026-09-10 — Пак ревью несёт секцию `checks` с путями этого диффа: зелёный пункт разработчика переносится вместе со своей шириной, непокрытое остаётся пробелом
- 4.15.0 — 2026-09-10 — Введена экономия контекста разработчика: погружение до первой правки пачкой чтений одним сообщением или дочерним исследователем с дайджестом, чтение диапазона по найденному вопросу, вывод команд сведён к тому, что решает вопрос, независимые вызовы одним сообщением
- 4.15.0 — 2026-09-10 — Проверки обеих ролей запускаются одним вызовом с выводом, сведённым к сбоям и итогу; на красном перезапускается только упавшая проверка
- 4.15.0 — 2026-09-10 — Ревьювер открывает файл диапазоном после поиска, а не целиком
- 4.14.0 — 2026-09-10 — **Breaking:** тела тестов вынесены из диффа в секцию `<tests>` — дайджест объявленных тест-кейсов по каждому файлу; ревью судит код и открывает тест под конкретное сомнение
- 4.14.0 — 2026-09-10 — Сигналы риска считаются только по коду изменения: пароли, SQL и права из тестовых фикстур больше не поднимают ложную тревогу
- 4.13.0 — 2026-09-10 — **Breaking:** ревью идёт одним проходом — три линзы применяются в одном контексте после одного чтения пака, дети остаются только для изменения, не влезшего в пак; убран флаг `--lines`, режим определяет обрезка диффа
