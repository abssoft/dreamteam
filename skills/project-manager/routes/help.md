# Help

Printed by the Help mode of `project-manager`: the fenced block below, with `$<label>` replaced by the manifest's `label` everywhere, the lines of the manifest's `help` appended before the closing line, and `пуш` lines kept only under `delivery: branch`.

```text
$<label> <KEY> — сводка задачи (read-only)
$<label> <KEY> <вопрос или просьба> — запрос по контексту задачи
$<label> [<KEY>] PRD [ультра] [идея, границы, решения] — интервью и документ в задаче
$<label> <KEY> разработка|Ревью [просто] [подряд] [гейт] [ультра] [модель <alias/slug>]
$<label> <KEY> сливай | пуш | разбей
$<label> создай [под <PARENT_KEY>] [PRD|разработка [просто]] [текст задачи]
$<label> стейдж [<KEY>|main] [стоп]

Голый ключ ничего не меняет: сводка, документы, подзадачи, маркеры и одна следующая команда.
Ключ + свободный текст без режима — запрос: агент понимает намерение по задаче (запускает PRD,
если текст явно просит документ; отвечает на вопрос; пишет продиктованный комментарий);
разработка, сливай и пуш — только по своему слову; в сомнении просит поставить конкретную задачу.
PRD (алиасы ПР, ТЗ) — интервью в этом же чате: агент пересказывает проблему, задаёт вопросы
раундами с рекомендованным ответом (❓/➡️), сам ищет факты в коде и трекере, по пустому
фронтиру пишет документ (Проблематика + Продуктовое решение: краткое описание, что
дорабатываем, что не дорабатываем, критерии приемки; риски, Scope, рекомендация по разбивке,
аналитика по запросу), переформулирует заголовок и записывает всё в задачу вместе с размером ->
стадия в трекере не трогается -> стоп (валидация человеком).
«Остальное по рекомендации» принимает рекомендованные ответы; «пиши»/«хватит» завершает
интервью. Без ключа задача создаётся после интервью. Существующий документ — базовая линия:
вопросы только о пробелах и изменениях; документ старого формата заменяется новым.
Работает и на подзадаче: документ пишется в саму подзадачу.
разработка — Разработка -> QA -> Ревью с тем, что есть в задаче (циклы ревью автоматически,
лимит returns из dreamteam.json; каждая принятая Разработка коммитится в ветке задачи, без push).
Подзадача: ветка от ветки родителя, принятая подзадача сразу вливается merge --no-ff в ветку
родителя и закрывается. Ветка задачи, открытая в основном дереве проекта, используется на месте.
просто (easy, легко) — модификатор разработки для маленькой правки без продуктовых секций;
на подзадаче работает только при явно указанном ключе.
гейт (gate) — модификатор разработки: в проекте без гейта QA (ключ checks в dreamteam.json)
разработчик задачи объявляет его в составе изменения; без гейта разработка и Ревью не стартуют.
подряд (все): выполнить все незавершённые подзадачи по очереди, стоп на первом блокере.
сливай — по политике delivery проекта: merge_push — commit + merge в базовую ветку + push,
затем уборка стейджа и дерева задачи; branch — всё незакоммиченное коммитится в ветку задачи,
подзадача вливается в ветку родителя, в origin ничего не уходит.
пуш — только при delivery branch — push ветки задачи (для подзадачи — ветки родителя) в origin
и удаление worktree; merge request в базовую ветку делает человек.
разбей: подзадачи по «Рекомендации по разбивке» из PRD, затем стоп. Каждая команда атомарна:
разработка подзадач начинается только по явной команде разработка.
создай (сделай): с командой разработка (просто) задача создаётся сразу (текст запроса — в
описание) и идёт в разработку; иначе — интервью PRD, затем задача с документом, стоп.
стейдж: сайты задач проекта по dreamteam.json — без ключа список с адресами, с ключом
поднять (уже запущенный вернёт адрес), стоп — остановить. Без ролей, трекера и Git.
PRD идёт на модели сессии — для него запускайте сессию на сильной модели.
Разработку и ревью можно вести на дешёвой модели: роли запускаются автоматически по таблице
моделей bootstrap: Разработка — по размеру задачи (размер из команды, иначе из трекера; XXL и
без размера — как XL), Ревью — по глубине изменения 1–5 из review-pack --check, исследование
PRD — по размеру; ультра (только по слову в команде) — верхняя ступень усилия для разработки,
ревью и исследования. Оверрайд на один прогон: модель <alias/slug> — одна модель на роли и
исследование прогона.
Настройки проекта — dreamteam.json в корне репозитория: base, delivery, returns, tracker,
references.terminology, checks, worktree, stage.
Требуются установленные роли DreamTeam: product-technologist, software-developer, qa-engineer,
code-reviewer, project-manager.
```
